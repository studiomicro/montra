## Goal

Beranda is the first screen a user sees every time they open the app, and the main journey's whole point is to
answer "how am I doing this month and what can I still spend today?" without typing anything
(`CLAUDE.md` › main journey, `docs/PRD.md:61`: "Beranda (one number, rupiah comparison, average per day, chart
picker)"). Today `/` is a static stub (`src/routes/(app)/+page.svelte:1-64`) with no load function, no real
figures and a permanent "Belum ada transaksi bulan ini." empty state. FN-07 gives the user one honest lever —
"how much can I spend a day for the rest of this month" — computed only from a stored budget amount and FN-05's
own transaction rows, never invented; FN-08 turns Beranda into the real hero screen that shows that number next
to this month's total, the comparison with last month, today's spending and three chart views, so that by the
time Gmail capture (FN-19) and the rest of Phase 2 land, there is already a home screen worth opening every day.

## Acceptance criteria

**Budget set / edit / delete (`setBudget`, `deleteBudget` actions on `/`)**

1. Given a space with no active budget row, when the user opens the budget `Sheet` from the "Atur anggaran" call
   to action and submits a positive whole-rupiah amount, then one `budgets` row is written
   (`space_id = locals.space.id`, `amount_minor` via `digitsToMinor`, never `parseFloat`), the sheet closes, and
   the safe-to-spend line appears without a page reload.
2. Given the same budget, when the page is reloaded (full refresh), then the budget and the safe-to-spend line
   it produces are still present — persisted state survives reload, not just the in-memory store.
3. Given an active budget, when the user reopens the sheet, changes the amount, and submits, then the row's
   `amount_minor` and `updated_at` are updated in a **single guarded statement** keyed on the previous
   `updated_at` (`UPDATE … WHERE space_id = ? AND deleted_at IS NULL AND updated_at = ? RETURNING *`, checklist ›
   Data access › "Concurrent writes") — never a read-then-blind-write.
4. Given two browser tabs with the budget sheet open on the same stale `updated_at` (pre-handoff "two tabs /
   stale forms" probe), when both submit, then the second is refused with "Berubah sejak terakhir dimuat" (and
   English), matching the pattern FN-04 already defines (`docs/features/fn-04-wallets/PRD.md:137-138`), never
   silently overwriting the first tab's write.
5. Given an amount of zero, blank, negative, or more than 13 digits, when submitted, then the action fails with
   a field error (`tr()`/English) and no row is written — amounts go through `amountDigits`/`digitsToMinor`
   (`src/lib/shared/amount-input.ts:7,31`), never a hand-rolled parse.
6. Given an active budget, when "Hapus anggaran" is submitted, then `deleted_at` is set (tombstone, content-free
   per `CLAUDE.md`), `seq` advances, and Beranda returns to the no-budget state (the "Atur anggaran" call to
   action reappears) immediately after the server confirms — reversible, the user can set a new one any time.
7. Given 20 concurrent `setBudget` submissions for a space with no existing budget (pre-handoff concurrency
   probe), when they race, then the partial unique index `(space_id) WHERE deleted_at IS NULL` lets exactly one
   insert succeed; the rest either update that same row (if the repo treats "insert failed on conflict" as
   "update instead") or fail cleanly — never two simultaneously active budget rows for one space.
8. Given JavaScript is disabled, when the budget sheet's form is submitted, then it still works as a normal form
   POST (progressive enhancement, checklist › Tests › pre-handoff "No-JS forms").

**Safe-to-spend math (the FN-07 "Mirror" line: `docs/FEATURES.md:79-81`)**

9. Given an active budget of `amount_minor = B`, this WIB month's total expense (excluding transfers) of `S`
   (both from the aggregate module, §Architecture notes), and `R` = remaining WIB days in the current month
   **inclusive of today** (`wibDaysRemainingInclusive`), when the safe-to-spend line renders, then it shows
   exactly `"Sisa {formatMoneyCompact(B - S)} · {formatMoneyCompact(floor((B - S) / R))}/hari untuk {R} hari"`
   (and the English equivalent) — rounding is always **floor**, never up, so the shown daily figure never
   overstates what is actually safe to spend (`CLAUDE.md` › "Money is never invented").
10. Given `B - S <= 0` (spending has met or passed the budget), when the line renders, then it shows
    "Sudah melebihi anggaran sebesar {formatMoneyCompact(S - B)}" (and English) in `--money-up` instead of the
    per-day split — a negative "per day" figure is never shown.
11. Given `R` is computed at 23:30 WIB on the last day of the month (pre-handoff WIB-boundary probe,
    `CLAUDE.md` › Verification), then `R = 1` (today still counts as a remaining day) and the shown total `S`
    excludes any transaction whose `occurred_on` falls on the 1st of the next WIB month, even if that
    transaction's UTC timestamp is still within the same UTC calendar day.
12. Given no active budget, when Beranda loads, then no "Sisa …" line is shown at all — the "Atur anggaran" call
    to action replaces it; the hero total and comparison pill still render normally (a missing budget never
    blocks the rest of the screen).

**Beranda display (the FN-08 "Mirror" line: `docs/FEATURES.md:84-87`)**

13. Given any state (zero or many transactions), when `/` loads, then the hero shows
    `"Pengeluaran {bulan}"` (current WIB month's Indonesian/English name) and this WIB month's total expense
    `S`, formatted via `moneyParts`/`formatMoney` (`src/lib/shared/money-format.ts:36,82`) — never hand-built.
14. Given this month's total `S` and the same-day-of-month-to-date total from last WIB month `S_prev` (Owner
    decision C), when the comparison pill renders, then `diffMinor = S - S_prev` is passed to `ComparisonPill`
    unchanged, which itself decides "lebih banyak"/"lebih hemat"/"hampir sama" via `comparisonKind` at the
    existing default threshold `5_000_000` minor = Rp 50.000 (`src/lib/ui/kit/category.ts:24-30`,
    `src/lib/ui/kit/ComparisonPill.svelte:11`) — this feature does not introduce a second threshold.
15. Given this month's total `S` and the current WIB day-of-month `N`, when the pill's average line renders,
    then it shows `floor(S / N)` as `avgPerDayMinor`, matching the existing `ComparisonPill` prop, never a
    separately hand-computed average shown elsewhere on the page.
16. Given the current WIB date, when Beranda renders, then "Hari ke-{N}" shows the WIB day-of-month (never the
    UTC day-of-month) — test vectors at 23:30 WIB and 00:30 WIB on month boundaries per `CLAUDE.md` ›
    Verification.
17. Given today's WIB expense total `T` and today's expense rows, when the "today" section renders, then
    `DayHeader` shows `T` as `outMinor` (and today's income, if any, as `inMinor`) and the list below it uses
    `GroupList`/`TransactionRow` keyed by transaction id, with the same figure `T` equal to the sum of the
    listed rows — the "totals reconcile" checklist item (`docs/ENGINEERING_CHECKLIST.md` › Money and dates), and
    specifically **Beranda's today total must equal Riwayat's today total for the same space and date filter**
    once FN-05's Riwayat screen exists.
18. Given zero transactions today, when the section renders, then the list area shows a muted
    "Belum ada transaksi hari ini." (and English) instead of an empty `GroupList`.
19. Given the `Segmented` chart picker, when the user switches between "Batang harian", "Per kategori", and
    "Vs bulan lalu", then the already-loaded data for all three renders without a new request (`BarChart` for
    the last 14 WIB days incl. today, tap-a-bar changes the readout per the component's own `selected` binding;
    `CategoryBar` for this WIB month's per-category split; `MonthLines` for this month vs last month aligned by
    day-of-month, truncated to the shorter of the two months' day counts).
20. Given the load is in flight, when `/` first renders, then skeleton placeholders show in place of the hero
    and chart (no flash of the zero-state before data arrives); given the load throws (D1 unavailable), then
    `ErrorState` with retry renders — never an unhandled 500 page.
21. Given the existing disabled Suara/Struk pills and "Segera hadir" caption
    (`src/routes/(app)/+page.svelte:14-22` today), when Beranda is rewritten, then they are kept verbatim in
    position (per the design system's "two big pills side by side" spec, `docs/design/DESIGN_SYSTEM.md:108-109`)
    — this feature does not enable or remove them.

**Cross-cutting (engineering checklist, every item that applies to this feature)**

22. Every load and action on `/` resolves the space through `locals.space.id` as already validated by
    `resolveCurrentSpace` in `hooks.server.ts` (`docs/features/fn-03-spaces/PRD.md:238-241`) — no route param
    or form field is trusted as a space id; a budget row belonging to a different space is never reachable
    through this feature's actions.
23. A pre-handoff cross-space probe (a second user, member of a different space, calling `setBudget`/
    `deleteBudget` against this space's budget id if one is ever exposed in a form field) is refused — no
    budget id is accepted from the client at all; the server resolves "the active budget for `locals.space.id`"
    itself, so there is no id for a cross-space probe to guess.
24. Every form body on the `setBudget`/`deleteBudget` actions is read within a size cap and answers 400 or 415,
    never 500, on a malformed or oversized body (reuse FN-01's `src/lib/server/forms.ts` guard, not a new one).
25. `{#each}` lists (today's transaction list, category chart segments) key by `transaction.id` /
    `category` key, never by merchant text or array index.
26. Every Indonesian phrase added for this feature (safe-to-spend line, over-budget line, "Hari ke-{n}", budget
    sheet copy, the 12 WIB month names, empty/error copy) has an English entry in `i18n-en.ts`; the coverage
    test fails the build if one is missing.
27. Currency display anywhere on `/` uses `formatMoney`/`formatMoneyCompact`/`moneyParts` from
    `src/lib/shared/money-format.ts`; no hand-built `Rp` string, and no money value is ever computed with
    `parseFloat` or floating-point arithmetic on minor units.
28. Focus returns to the opener when the budget `Sheet` closes; touch targets ≥ 44 px (including the chart
    picker's `Segmented` options and `BarChart`'s tappable bars); WCAG AA contrast in both themes, including the
    `--money-up` over-budget line (reuses FN-00's token system, no new colours).
29. User-facing error text on this feature never contains a file path, stack trace, row id, or internal
    identifier.
30. `npm run gates` (check, lint, test, build) is clean on the branch before hand-off; every new regression test
    (budget stale-`updated_at` race, 20-way concurrent `setBudget`, WIB 23:30/00:30 boundary vectors, floor
    rounding on the safe-to-spend split, "Beranda today total = Riwayat today total") is shown failing on the

## Architecture notes

**Modules touched / added**

- `src/lib/server/db/schema.ts` (currently only `appMeta`, `src/lib/server/db/schema.ts:1-8`) — add one table,
  migration generated into `migrations/0005_budgets.sql`:
  - `budgets (id pk text, space_id text not null references spaces.id, amount_minor integer not null,
    currency text not null default 'IDR', created_at integer not null, updated_at integer not null, deleted_at
    integer, seq integer not null)`. A **partial unique index** `idx_budgets_one_active_per_space ON
    budgets(space_id) WHERE deleted_at IS NULL` enforces "at most one active budget per space" at the SQL
    level (SQLite/D1 supports partial indexes; this is simpler and stronger than the application-level guard
    FN-04 used for "one favourite wallet", because here there is genuinely only ever zero or one row, not a
    toggle between many — `docs/features/fn-04-wallets/PRD.md:203-205` explains why FN-04 could not use this
    approach for its own, different, invariant).
  - `seq` assignment: reuse whatever shared `nextSeq(db, spaceId)` helper FN-03/FN-04 lands by the time this
    feature is implemented (check first per the precedent at `docs/features/fn-04-wallets/PRD.md:210-214`); fall
    back to the same `app_meta`-keyed counter pattern only if no shared helper exists yet.
- **`src/lib/shared/dates.ts`** (new): WIB (UTC+7, no DST) calendar-date helpers, pure functions, no I/O —
  exported for FN-05, FN-09, FN-25 and everything else that buckets by `occurred_on` to reuse:
  - `wibDateString(epochMs?: number): string` — `'YYYY-MM-DD'` for the given instant (default now) in WIB.
  - `wibDateParts(date: string): { year: number; month: number; day: number }`.
  - `daysInWibMonth(year: number, month: number): number`.
  - `wibDayOfMonth(date: string): number`.
  - `wibDaysRemainingInclusive(date: string): number` — `daysInWibMonth(y, m) - day + 1`; the exact divisor
    criterion 9 requires.
  - `wibMonthRange(date: string): { fromDate: string; toDate: string }` — first/last day of that WIB month.
  - `wibPreviousMonthRange(date: string): { fromDate: string; toDate: string }`.
  - `wibMonthName(date: string, locale: 'id' | 'en'): string` — returns the month name directly (not through
    `tr()`, since this module must stay free of the i18n-context dependency per `CLAUDE.md` › "shared domain
    code... so the client and Worker run the same logic"); the 12 Indonesian names used here are still added as
    standalone `msg()`-wrapped phrases with English entries in `i18n-en.ts` so the coverage test covers them too
    (the page component calls `tr(monthNameId)` when it needs the *translated* label, e.g. for the hero and the
    comparison pill's `monthName` prop).
  - `wibLast14Days(epochMs?: number): string[]` — the 14 WIB dates ending today, oldest first, for the
    `BarChart` x-axis.
- **FN-05 aggregate module contract** (not built by this feature — `src/lib/server/transactions/aggregate.ts`,
  FN-05's deliverable; **this feature is blocked until it exists** — do not stub a "pretend" aggregate, per the
  same reasoning FN-04 applied to the FN-03 space-access helper, `docs/features/fn-04-wallets/PRD.md:224-226`,
  and per `CLAUDE.md` › "Money is never invented"). The exact functions this feature calls, so FN-05's author and
  this feature's implementer agree on the shape before either writes code:
  - `sumExpenseMinor(db, spaceId, fromDate, toDate): Promise<number>` — non-negative integer minor-unit total of
    expense transactions (never transfers) with `occurred_on` in `[fromDate, toDate]` inclusive (WIB date
    strings), `deleted_at IS NULL`. Returns a **non-negative magnitude** regardless of whatever sign convention
    FN-05's schema stores expenses with internally (`CLAUDE.md` leaves that convention to FN-05; this contract
    does not need to know it).
  - `sumExpenseByCategoryMinor(db, spaceId, fromDate, toDate): Promise<{ category: CategoryKey; amountMinor:
    number }[]>` — same filter, grouped by the category key the kit's `CategoryBar`/`TransactionRow` already use
    (`src/lib/ui/kit/category.ts:3-19`), sorted by amount descending, zero-amount categories omitted.
  - `sumExpenseByDayMinor(db, spaceId, fromDate, toDate): Promise<{ date: string; amountMinor: number }[]>` —
    one row per WIB date in range, **zero-filled** for days with no transactions (so `BarChart`'s 14-bar axis
    never has a gap), computed in SQL (`GROUP BY occurred_on`), not by loading every row into the Worker
    (checklist › Data access › "Bounded work").
  - `listExpensesForDay(db, spaceId, date): Promise<{ id: string; title: string; categoryMeta: string;
    amountMinor: number; category: CategoryKey; status?: string }[]>` — shaped to pass straight into
    `TransactionRow` props (`src/lib/ui/kit/TransactionRow.svelte:8-24`), for today's list.
  - All four take **already-validated** `spaceId` (this feature passes `locals.space.id`, never a client value)
    and bounded date ranges; all run against D1 with parameterised, indexed queries on `(space_id, occurred_on)`
    (checklist › Data access › "Bounded work").
- `src/lib/server/budgets/repo.ts` (new): `getActiveBudget(db, spaceId)`, `upsertBudget(db, spaceId,
  amountMinor, expectedUpdatedAt: number | null)` (guarded `UPDATE … RETURNING` when a row exists and
  `expectedUpdatedAt` is given, else a guarded `INSERT` relying on the partial unique index to prevent a race —
  criterion 7), `deleteBudget(db, spaceId, expectedUpdatedAt)`.
- `src/lib/server/budgets/validation.ts` (new): zod schema for the amount field, built on
  `amountDigits`/`digitsToMinor` (`src/lib/shared/amount-input.ts:7,31`) — rejects zero, negative, blank, or
  over-length input (criterion 5); no new money-parsing logic.
- `src/routes/(app)/+page.server.ts` (new) and `src/routes/(app)/+page.svelte` (rewrite of
  `src/routes/(app)/+page.svelte:1-64`) — as described in Scope.
- `src/lib/shared/money-format.ts` (`formatMoney`, `formatMoneyCompact`, `moneyParts`,

## Owner decisions

**Answered by the owner 2026-10-08: accept every proposed default below as written.**


The following are genuinely open for this pass; proposed defaults are used unless the owner overrides them
before build.

- **A. "Hampir sama" threshold.** *Proposed default:* keep the value already hard-coded as `ComparisonPill`'s
  default, `sameThresholdMinor = 5_000_000` minor = **Rp 50.000**
  (`src/lib/ui/kit/ComparisonPill.svelte:11`, already covered by `src/lib/ui/kit/category.test.ts:15-22`) —
  this feature passes no override, so it is adopted implicitly. *Trade-off:* Rp 50.000 is a small band for a
  user whose monthly spending is in the tens of millions (it will read "lebih banyak"/"lebih hemat" for almost
  any real difference); if the owner wants a wider "about the same" band (e.g. a percentage of last month's
  total) that is a change to the shared component's default, not to this feature.
- **B. Per-category budgets this pass, or deferred.** `docs/FEATURES.md` FN-07's own "Mirror" line only
  describes the single, total "set a budget once" flow (`docs/FEATURES.md:79-81`); per-category budgets are not
  in the catalog's FN-07 mirror note at all. *Proposed default:* defer per-category budgets entirely — ship the
  one total monthly budget only. *Trade-off:* a household manager who wants to cap "Makan & Minum" separately
  from "Hiburan" has no way to do that yet; the schema (`budgets.space_id` unique-when-active) does not block
  adding a `category_id` column and a second unique shape later, but that is a new migration, not a column this
  pass pre-builds unused.
- **C. Comparison basis: same-day-to-date vs. last month's full total.** *Proposed default:* compare this
  month-to-date (WIB day 1 through today) against **last month's total through the same day-of-month**
  (capped to last month's day count), not last month's full total — a full-month total compared against a
  partial month would make every comparison early in the month look like "much less," which is not an honest
  reading. *Trade-off:* on the 1st of a new WIB month the comparison is based on just one day in each month,
  which can look noisy for a small sample; the Rp 50.000 "hampir sama" band (decision A) dampens some of that
  noise but not all of it — a minimum-sample guard (e.g. hide the pill before day 3) is not built this pass.
- **D. Calendar view in the chart picker.** `docs/FEATURES.md`'s FN-08 mirror note lists "calendar" alongside
  daily bars, per category, and vs last month. *Proposed default:* defer the calendar view — ship the other
  three (`BarChart`, `CategoryBar`, `MonthLines` already exist in the kit and need no new component; a calendar
  grid does not exist yet and is a larger, separate UI-kit addition). *Trade-off:* "tap a day to see its figure"
  from a month-grid view is not available this pass; the 14-day bar chart's own tap-a-bar readout
  (`src/lib/ui/kit/BarChart.svelte:43-48`) covers the same need for the last two weeks only, not the whole
  month.
- **E. Reversible budget ("Hapus anggaran").** *Proposed default:* allow clearing the budget back to the
  no-budget state (criterion 6), matching the reversibility `CLAUDE.md` expects of tombstones elsewhere (e.g.
  FN-04's archive/restore). *Trade-off:* none significant — this is a small addition over "set once," included
  because the alternative (a budget that can only ever be changed, never removed) would trap a user who set one
  by mistake with no way back to the plain Beranda view.
- **F. Safe-to-spend rounding.** *Proposed default:* **floor**, never round up or to the nearest unit (criterion
  9) — showing a daily figure a few rupiah higher than what is truly left would be a small but real instance of
  inventing money. *Trade-off:* the displayed total of `perDay × remainingDays` can be a few rupiah less than
  the actual remaining budget; this is the safe direction to err in, not a defect to fix.
- **G. Budget identity: one persistent value, or a value per calendar month.** *Proposed default:* one
  persistent `budgets` row per space with no month-scoped history (Out of scope, this section) — "set a budget
  once" (`docs/FEATURES.md:79`) reads as a standing monthly figure, not something re-entered every month.
  *Trade-off:* a user who raises their budget mid-month immediately sees a larger "Sisa" for the *current* month
  with no record that the earlier, smaller figure ever applied; if the owner later wants Laporan (FN-09) to show
  "your budget was X in September," that needs a new, period-scoped table, not a column added to this one.
