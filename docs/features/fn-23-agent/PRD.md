# FN-23 Agent (beta) (`/agen`)

Risk tier: **Large** (new table + migration 0036, background jobs path in `workers/jobs`, new AI path, R2 files the user downloads, plan gating, touches account and space delete, export classification, cron).
Slug: `fn-23-agent`. Branch: `feat/fn-23-agent` (from `integrate/2026-10-10`).

## Goal

FN-23 is the "ask, and the Agent does it" feature of the Agent plan (docs/FEATURES.md:304-308): a signed-in Agent-plan user picks a report, watches visible steps ("membaca 1.234 transaksi" → "mengelompokkan per kategori" → "ringkasan bulanan" → "siap diunduh"), and downloads files. Three report types: a **monthly report**, an **annual recap** and an **asset list for the yearly tax return (SPT)**. It gives the Agent plan (FN-30 `agentEnabled`) something to deliver and closes the "wire `agentEnabled` into FN-23's entry point" follow-up. Money is never invented: every figure in every file comes from code over the user's stored rows, the same helpers Beranda, Laporan, Dompet and Tanya use. The AI (user's own Anthropic key, through AI Gateway) writes only an optional short narrative, which must pass Tanya's figure guard; if the model is unavailable or its text is rejected, the report is still complete, without narrative. Information only: not tax, financial or legal advice; the asset list is information from the user's records, not an SPT filing. Mirror behaviour only, no comparable apps brand or copy.

## Owner decisions (defaults chosen; owner said to proceed with these)

1. **Runtime: Cloudflare Queue steps on the existing `JOBS_QUEUE`, state in D1. No Workflow, no Agents SDK, no Durable Object.** Why: (a) the app Worker would need a cross-script Workflow binding in both wrangler envs just to start an instance, and a Workflow cannot be exercised in vitest; the producer binding it needs already exists. (b) The step machine must live in D1 anyway so the page can show progress. (c) The pattern is proven here (Gmail scan pages: id-only messages, idempotent per page, stalled work re-sent by the cron sweep). (d) Handlers are plain functions behind `handleBatch` deps, so tests run on local D1. Trade-off accepted: we write a small guarded state machine (5 steps) instead of Workflow's durable steps; revisit a Workflow if a step ever needs minutes of CPU, a long sleep or fan-out. CLAUDE.md lists "Workflows for … agent reports" as the intended direction; this is a documented deviation, like FN-22's (`TASKS.md:148`), approved by the defaults line above. No `wrangler.jsonc` change in either Worker.
2. **Plan gating:** Agent plan only (`agentEnabled(await planOf(db, locals.user.id, now))`), re-checked on the server in the page load, every action, the download route, and in the job at the first and last step. A lapsed plan: new runs refused, downloads refused (403, "Paket Agen berakhir"), existing files and rows stay until their 30 days. Non-Agent users see a locked page with a link to `/pengaturan/paket`; no form, no list.
3. **Limits (proposed):** 1 unfinished (queued/running) run per user; 3 unfinished per space; **5 new runs per user per rolling 24 h; 15 per space per rolling 24 h**; at most 20 live reports per user per space (older ones can be deleted by the user). Counted in one guarded SQL statement (AC 6). A refused request creates no row.
4. **Credits: no credit debit.** FN-30 defines no debit hook (nothing writes `ai_capture_spend`), the plan is already paid, and with BYOK the user pays Anthropic directly for the one narrative call. The checklist's "metered" item is met by recording the call's token counts on the run row for FN-42's usage page (not wired into `/pengaturan/pemakaian` this pass). If the owner later wants a per-report credit price, it is a one-line guarded ledger insert in the create action.
5. **Retention: 30 days from when the report is ready** (`expires_at = ready_at + 30 days`; an unfinished or failed run expires 7 days after creation). Expiry deletes the R2 files (via `file_deletions`) and the whole run row (facts included). Also deleted on: user "Hapus" of one report, account delete, space delete. Done by the jobs cron sweep (AC 14); every read also filters `expires_at > now`, so an expired report is invisible even before the sweep.
6. **Visibility:** any live member of the space with the Agent plan can create a report for that space; **only the member who created it can see or download it** (files hold the whole space's figures; a shared-space member who leaves loses access immediately because every read repeats the live-membership check).
7. **Formats: CSV + a self-contained printable HTML. No PDF this pass.** A PDF needs either Browser Rendering (a new paid binding and an unverified product) or a JS PDF library with embedded fonts (bundle weight, U+2212 and Indonesian text need a Unicode font). The HTML has a print stylesheet, so "Cetak / Simpan sebagai PDF" is one tap in the user's browser. Both are served as attachments (AC 11). Revisit PDF when the owner wants a server-made one.
8. **Narrative is optional and AI-only for monthly/annual.** One provider call, no tool loop (the report structure is fixed, so the facts are computed by code first and handed to the model as data). The SPT asset list **never** calls the model (a table of records needs no prose, and it lowers the AI surface for the most sensitive report). The form has a "Tulis ringkasan dengan AI" checkbox, default on when gateway + key exist, disabled with the reason otherwise.
9. **Model:** `AGENT_MODEL = RECEIPT_MODEL` (same Sonnet id as Tanya); engineer re-checks the models page on build day. `max_tokens` 800, call timeout 30 s, no pricing figure written anywhere.
10. **Periods:** month = any past month with at least one live non-demo transaction, plus the current month (labelled "sampai {tanggal}"); year = same for years. SPT asset list: a year (current year = "per {tanggal}", past year = "per 31 Desember {tahun}"). A request for an empty period is refused with "Belum ada catatan di periode ini" and consumes no cap.
11. **Asset-list year-end honesty:** only wallet balances can be computed as of 31 December (opening balance + signed rows up to that date). Net-worth items, belongings and collectibles keep no value history, so they are listed with their **latest known value, labelled with the date the report was made**, plus acquisition date/price where the record has it (belongings and collectibles have purchase price and date; net-worth items have an optional acquired-on date). Items whose recorded acquisition date is after 31 December of the chosen year are left out; items without a date are included and marked "tanggal perolehan tidak dicatat". Archived wallets and `Data demo` rows are left out. Multi-currency: each currency listed and subtotalled on its own, never summed or converted.
12. **Language:** the report is written in the language of the user's session at request time (stored on the run, because the jobs Worker has no cookie).

### Server (`src/lib/server/agent/`)
- `facts.ts`: builds the deterministic dataset of a run, step by step, from the same helpers Tanya's tools call, over `readOnlyDb(db)`. Typed with zod (`agentFacts` schema; money as integer minor units + currency, dates as WIB strings; ≤ 3 currencies). Functions per step (below). No model, no HTTP here. Exposes figures to a `FigureBook` (the narrative step builds the book from the stored facts, so the narrative figures and the file figures come from the same numbers and the same `formatMoney`).
- `steps.ts`: the step state machine (`stepsOf(type)`, `runNextStep(deps, runId, attempts, now)`), idempotent and lease-guarded (AC 7-9).
- `narrative.ts`: one call through `askClaude` (extended with an optional `tools` omission, see Architecture), static `AGENT_NARRATIVE_PROMPT` (versioned constant, no user data), user message = facts as data (labels, `figure_id`, formatted text, cleaned names via `dataText`, period, currency), output through `guardAnswer`.
- `render.ts`: pure functions `renderCsv(facts, narrative, translator)` and `renderHtml(...)`: deterministic (same facts + narrative + locale → same bytes; no clock reads, the generated-on date is in the facts), all text cells through `csvLine`, HTML via one escape function for every interpolated value (names, notes, wallet/item names, narrative), inline `<style>` with a `@media print` block, no script, no external resource, no image. Account-number-like digits in names/notes masked with `maskAccountNumbers` (`src/lib/shared/text.ts`) as the export does. Disclaimer text in both files.
- `repo.ts`: `createRun` (one guarded `INSERT … SELECT … WHERE` with the caps, AC 6), `getRun`/`listRuns` (by user + space, live only), `claimStep` / `finishStep` (compare-and-set), `markReady` (one `db.batch`: update + `keepKey` for both files), `deleteRun` (outbox insert + delete in one batch), `sweepAgentRuns(db, now)` (expired + stalled, bounded).
- `files.ts`: R2 write with the outbox discipline of `photos/store.ts` (reserve key, put, then keep inside the row-updating batch); `agentFileKey(spaceId, runId)` → `spaces/<spaceId>/agent/<runId>/<uuid>.<ext>`; `PhotoKind` generalised (or a sibling `FileKind`) rather than a second outbox.
- `messages.ts`: every user-facing server string via `msg()`.
- Shared: `src/lib/shared/agent.ts` (types `AgentType`, `AgentStatus`, step ids and labels, caps, period parsing/validation, zod for the form), `src/lib/shared/jobs.ts` gains `z.object({ type: z.literal('agent_run'), runId: id })`.
- Jobs Worker: `workers/jobs/src/queue.ts` gets a `agentRun(runId, attempts)` dep and a `case 'agent_run'`; `workers/jobs/src/index.ts` wires it (db, env for AI, `env.FILES`, `env.CACHE` for the price book, `env.JOBS_QUEUE` to enqueue the next step) and adds `sweepAgentRuns` to the cron tick before the file sweep, in its own try/catch.

### The five steps (idempotent; one queue message per step, ids only)
Labels shown on the page (Indonesian; English entries required). Each step does bounded work, stores its result in `agent_runs.facts_json` through a compare-and-set on `steps_done`, then enqueues `{type:'agent_run', runId}` for the next step.

| # | Monthly / Annual | SPT asset list |
| --- | --- | --- |
| 1 | `read`: count live non-demo rows in the WIB range (`periodTotals`; refuse if 0); store counts per type + currencies | `read`: list live wallets (≤ 50) and the asset sources (items ≤ 200, belongings ≤ 300, collectibles ≤ 300) and store how many of each |
| 2 | `group`: `categoryTotals` (expense, top 10 + "Lainnya" per currency), `merchantTotals` top 10 | `balances`: wallet balances at year end (new `upTo` date on the wallet sum, AC 17) |
| 3 | `summary`: monthly: income/expense/net, previous-month comparison (`periodTotals` of the prior month, `floorPercent`); annual: `monthlyTotals` (12), highest/lowest expense month computed by code | `assets`: net-worth items valued from the cached price book, belongings (`belongingValue`), collectibles; subtotals per currency |
| 4 | `narrate`: optional AI call + guard (skipped when off/unavailable; stores the narrative or the skip reason) | (no step; the list has 4 steps) |
| 5 | `render`: build CSV + HTML, write both to R2, `markReady` | `render` |

A plan that lapses between steps ends the run `failed` (code `plan`) at the next step and render writes no file. Table-driven over the three plans; `agentEnabled` is the only gate used.
2. (A) Signed out: `/agen` redirects to `/masuk` with the shared safe-return helper (never `startsWith('/')`); actions and download refuse without a session.
3. (A) Two users, two spaces: user A's run id requested by user B (same space), by a member of another space, by a removed member and by a signed-in non-member gets the same 404 (status, body, timing class) as an unknown id; list and download never return another user's or space's rows. A live member who is not the creator cannot see the run. Run for 101+ wallets/runs-per-space does not use a growing `inArray` (`json_each` bind).
4. (A) The create action ignores any `spaceId`/`userId`/`status`/`type`-outside-enum field; `type` and `period` are validated with zod (enum, month/year not in the future, not older than 10 years); unknown values answer 400 with a form message, never 500.
5. (A) Form bodies go through `readFormBody` (size cap, 400/415, prototype-safe); an oversized or `text/plain` body is refused without creating a row.

Limits and concurrency
6. (A) Caps hold exactly: 20 concurrent `?/buat` requests from one user create at most 1 unfinished run; 20 from one space create at most 3; the 6th run in 24 h for a user and the 16th for a space are refused with a distinct message; each is one guarded `INSERT … SELECT … WHERE` inside one `db.batch` (checklist: concurrent writes). A refused request creates no row and enqueues nothing. A double submit (same `requestId`) returns the existing run, enqueues nothing twice, and does not count twice.

Queue, steps, retries
7. (A) Each step is idempotent: delivering the same `agent_run` message twice, or two deliveries at once, runs each step's side effects once (compare-and-set on `steps_done` plus a lease of 120 s); a message for a finished, failed, expired or unknown run is acked and does nothing; a message never carries more than `{type, runId}`.
8. (A) A step that throws leaves `steps_done` unchanged so the retry repeats only that step; a step that completes but whose next enqueue fails throws (queue retry), and the redelivery continues from the next step without redoing the finished one. After `attempts` > 6 on one run, or 3 failed deliveries of one step, the run is `failed` (code `internal`) and its partial facts are cleared. Test with a fake queue that fails the k-th send for each k.
9. (A) A stalled run (status queued/running, `updated_at` older than 5 minutes, lease expired) is re-enqueued by the cron sweep (≤ 50 per tick) and a run stalled over 30 minutes is marked `failed`; the sweep never re-enqueues a run that progressed meanwhile.
10. (A) The `handleBatch` switch is exhaustive (the `never` check at `queue.ts:131` still compiles); an invalid message is retried and logged without its body.

Files and R2
11. (A) CSV and HTML are written to `FILES` under `spaces/<space_id>/agent/<run_id>/<uuid>.<ext>`; the key never contains request text; both keys are reserved in `file_deletions` before the put and removed by `keepKey` in the same batch that marks the run `ready`; a crash after the put but before `markReady` leaves the keys due for deletion (test). Download headers are exactly those in Scope (attachment, fixed content types, nosniff, no-store, sandbox CSP); no `unsafe-inline` anywhere.
12. (A) Determinism: rendering the same facts + narrative + locale twice yields byte-identical CSV and HTML; a retried `render` step ends with one `ready` run and no stray live object (the first attempt's keys are in the outbox).
13. (A) CSV safety: every cell goes through `csvLine`; category/wallet/item/merchant names such as `=HYPERLINK("x")`, `+1`, `-2`, `@SUM(A1)`, tab-prefixed and fullwidth `＝` come out prefixed with `'`; amounts via `formatCsvAmount` (no floats). HTML safety: names containing `<script>`, `"><img onerror>`, `&`, 10 KB notes are escaped/truncated; the output contains no `<script`, no `on*=` attribute and no external URL.
14. (A) Retention: a run `ready` for 30 days (clock injected; test at 29 d 23 h and 30 d 0 h) disappears from the list and download (404) even before the sweep; the cron sweep then moves both keys to `file_deletions` (due now) and deletes the row in one batch, bounded to 100 runs per tick, and `sweepFileDeletions` removes the objects; unfinished/failed runs expire 7 days after creation; a user's "Hapus" does the same for one run, only the owner's.
15. (A) Account delete and space delete: the user's runs (all spaces, including shared spaces that survive) and the space's runs are deleted and their keys land in the outbox in the same batch (`purgeSpaces`, `delete-account.ts`); the export-table test passes with the new decision; `sweepFileDeletions` also treats a key still held by a live `agent_runs` row as referenced.

Money, dates, reconciliation
16. (A) Integers only: facts and files carry `amount_minor` integers and ISO currency; no `parseFloat`/float arithmetic on money; percents via `floorPercent` (null on a zero base); formatting only through the shared formatter (`Rp 1.250.000`, `−Rp 25.000` with U+2212 in HTML; CSV uses `formatCsvAmount`); at most 3 currencies, each reported separately; a sum past the safe-integer range is shown as "terlalu besar", never rounded. Transfers, adjustments and `is_demo` rows never count (same helpers).
17. (A) Reconciliation: for the same period, the monthly/annual report's income, expense, net, count, category and merchant figures equal `periodTotals`/`categoryTotals`/`merchantTotals` (hence Beranda, Riwayat and Laporan); the sum of monthly rows equals the annual totals; the asset list's wallet balances for "today" equal Dompet's `balanceTotals`, and its year-end balances equal opening + signed rows with `occurred_on <= <year>-12-31` (new optional `upTo` on `walletTransactionsSums`, default unchanged so every existing caller is unaffected: existing tests still pass). Month-boundary vectors: a row at 23:30 WIB on 31 Dec and one at 00:30 WIB on 1 Jan land in the right year/month. Leap-year range (366 days) is accepted by `boundedRange`; a wallet created after year end with no earlier rows is left out.
18. (A) Asset list scope: only data that exists is included (wallets, net-worth items incl. debts as liabilities, belongings, collectibles); items acquired after year end are excluded, undated items marked; item lines show "nilai terakhir per {tanggal laporan}", never claim to be the 31 December value; unpriced items ("Belum ada harga") appear with an empty value and a note, never a guess; the disclaimer is in both files.

## Architecture notes
- **New:** `src/lib/server/agent/{facts,steps,narrative,render,repo,files,messages,prompt}.ts` (+ tests), `src/lib/shared/agent.ts`, `src/routes/(app)/agen/{+page.server.ts,+page.svelte}`, `src/routes/(app)/agen/[id]/unduh/+server.ts`, `src/lib/ui/agent/*` only if a row/steps component is needed (compose from kit), migration `0036_agent_runs.sql` + snapshot/journal, `scripts/compat-agent.*`.
- **Edit:** `nav.ts` (+test), `schema.ts`, `spaces.ts` (`SPACE_SCOPED_TABLES`, `purgeSpaces` release step before the deletes), `auth/delete-account.ts` (release + delete by `user_id`), `export/tables.ts`, `photos/store.ts` (key kind + sweep reference guard, additive), `shared/jobs.ts`, `workers/jobs/src/{queue,index}.ts`, `i18n-en.ts`, `docs/RUNBOOK.md`, `.dev.vars.example` (`COMPAT_AGENT_ANTHROPIC_KEY`).
- **Small additive changes to Tanya modules (no behaviour change for Tanya):** `FigureBook.count(label, n)` (a locale-grouped integer for transaction counts; the guard rejects raw 4+ digit numbers, so counts must be placeholders too); `askClaude` accepts an `AskRequest` with `tools` omitted (send no `tools` field) and the engineer re-checks the live docs for whether `thinking: { type: 'between_tools' }` is valid without tools, else sends no `thinking` for this call (unverified here, NOT assumed); `walletTransactionsSums(db, spaceId, upTo?)`.
- **Reuse, don't fork:** gateway/key/classification from `ai-keys`; `readOnlyDb`, `dataText`, `resolvePeriod`/`boundedRange`, `FigureBook`, `guardAnswer` from `tanya/`; aggregate/balance/net-worth/belongings/collectibles helpers; `csvLine`/`formatCsvAmount`; the `file_deletions` outbox; `createTranslator`; `currentSpaceScope`/`requireSpaceAccess`; kit components.
- **Worker split:** the app Worker creates the run and enqueues step 1 (`JOBS_QUEUE.send`; if the send fails the row stays `queued`, the cron sweep re-sends it, and the page says "Antre"); everything else runs in the jobs Worker. The download is served by the app Worker.
- **Where the AI key is opened:** in the jobs Worker, for the run row's `user_id` only. The jobs Worker already has the secrets (`workers/jobs/src/env.d.ts`); if they are unset the narrative is skipped with reason `ai_unconfigured`, the report still completes.
- Rows in `facts_json` are plaintext D1 like the transactions they come from (FN-21 sealing is for uploaded files); the column is nulled when a run fails and the row is deleted at expiry.
