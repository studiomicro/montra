## Deviations judged (per the senior-software-engineer's own report)

- **F1 — reduced-motion `MascotLoading` keeps the `<svg>` node in the DOM, hidden by CSS, instead of never rendering it** (AC20). Judged **acceptable, non-blocking**: the only way to literally satisfy "no SVG in the reduced-motion render path" is a client-side `matchMedia` check gating the markup, which SvelteKit's SSR cannot do server-side and which would introduce a hydration-timing flash the PRD never asked for. The shipped behaviour — `aria-hidden`, `display: none`, confirmed invisible and non-animating in a real browser with `reducedMotion: 'reduce'` — delivers the intent ("never a static, non-animating mascot image") exactly. Recommend the PRD wording be corrected in a future pass rather than re-opening this cycle.
- **F2 — rects are one per horizontal run of same-colour pixels, not one per pixel** (Part 1 prose, not a numbered AC). Judged **acceptable**: `Mascot.test.ts` "runs cover exactly the drawn pixels of a frame" proves the run-length encoding round-trips to the identical pixel grid; the rendered SVG is pixel-identical either way, still inline-only, still `crispEdges`, still one theme-token class per rect (AC3/4 verified above). This is a reasonable implementation optimisation (smaller markup) with no visible or accessibility difference, and the review goal ("a change to Koko's pixels is a reviewable diff") is preserved via the separate pixel-grid snapshot test, independent of the rect encoding.
- **F3 — favicon viewBox is `0 0 24 24`, not the PRD's stated `0 0 32 32`** (Part 5 prose, not a numbered AC). Judged **acceptable**: `test/icons.test.ts` locks in 24×24 deliberately, matching Koko's own pixel grid (`GRID = 24`) and `Mascot.svelte`'s own viewBox convention, more literally "the same crisp-pixel `<rect>` technique as `Mascot.svelte`" than a 32×32 canvas would be. SVG favicons scale freely in the browser tab regardless of viewBox units; there is no numbered acceptance criterion tied to the exact value, no AC references a 32×32 requirement, and no visual or functional defect results.

None of F1-F3 touch money, space authorization, sync, or any numbered acceptance criterion's pass/fail outcome; all three are explicitly tested and documented, not silent.
