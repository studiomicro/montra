## F1 — enum-sync test (`test/integration/schema-enum-sync.test.ts`)

- Opens a local D1 with every migration applied (`openLocalD1`), reads every `CREATE TABLE` from
  `sqlite_master`, and parses each string-literal comparison on a column inside it (`col in (...)`,
  `col = '…'`, `<>`, qualified, `__new_*`-qualified, backticked or bare) with `test/helpers/check-enums.ts`
  (unit-tested in `test/helpers/check-enums.test.ts`: glob/like patterns, `length(x) = 10`,
  `typeof(x) = 'integer'` and comments are ignored).
- The TS side is every drizzle column declared with `enum:` in `schema.ts` (`getTableConfig(...).columns[].enumValues`),
  which is the shared source array (`TRANSACTION_SOURCES`, `MODULES`, `PLANS`, …) or the inline literal list.
- Rules: for every enum column, every CHECK value must be in the TS enum, every TS value must appear in some
  CHECK, and a column with no CHECK mention fails; a value **list** on a column with no TS enum fails.
  `NARROWED` names the three deliberate subsets with their own TS array (`plan_changes.to_plan`,
  `billing_events.plan`, `vouchers.plan` → `PAID_PLANS`). Today: no drift on any enum column.
- A synthetic case proves each failure message; a D1 insert of `feature_flags.module = 'bukan_modul'` proves the
  parsed SQL is the enforced constraint.
- **Fail-before:** with `RECURRING_STATUSES` given a fourth value `'archived'` (no migration) the test failed with
  `"recurring_transactions.status: TS has archived, the CHECK does not"`; file restored with
  `git checkout -- src/lib/shared/recurring.ts`, test green again.
- Triggers (e.g. 0024's `day_closures` format triggers) are not parsed: they hold no enum lists.
