## Binding to FN-05 (no parallel insert)

- `transactions/repo.ts`: the insert is now `insertTransactions(db, scope, rows, now, guard?)` — one
  `INSERT … SELECT … FROM json_each(?)` with the membership, `refsHold` (now SQL-expression based, same rule
  for update), the per-space cap (`count + rows ≤ 100 000`) and an optional per-row caller guard.
  `createTransaction(db, scope, input, now, origin = { source: 'manual', dedupeKey: null })` is a one-row call
  of it (additive fifth argument; every FN-05 call site unchanged, all FN-05 tests green).
- `transactions/validation.ts`: the zod schema is split into `fieldsSchema` (shared) + `draftSchema` (form, adds
  typed digits). `capturedTransactionInput` validates a stored draft with `fieldsSchema` and the same ref rules
  (`refErrors`, extracted from `resolveTransactionInput`), keeping the exact minor amount (sen not truncated)
  and refusing a wallet in another currency (`CURRENCY_MISMATCH`).
- `saveDrafts` = one `db.batch`: seq bump → `insertTransactions` (each row guarded by "its draft is still
  pending at the loaded `updated_at`") → tombstone the drafts with `saved_transaction_id` (only where that
  transaction exists) → `batchAssert` that every draft was saved. Any shortfall (stale draft, archived wallet,
  removed member, cap) or a dedupe UNIQUE violation rolls the whole batch back: nothing saved, 409 with a clear
  message. `batchAssert` (`src/lib/server/db/assert.ts`) is a select builder that evaluates `json('…')` on
  non-JSON text when the condition fails (SQLite has no RAISE outside triggers); verified against local D1.
  Bulk "Atur kategori"/"Atur dompet" use the same all-or-nothing helper. 4 statements per batch regardless of N.

## Decisions taken in this cycle (my recommendation, adopted)

1. **Atomic save over per-draft writes.** The brief's "one guarded db.batch, partial failure → nothing saved"
   is implemented with `batchAssert`; incomplete drafts are excluded before the batch (owner decision B), so
   only a change *during* the request aborts it.
2. **Stale guard on every bulk action**: checkbox values are `<id>:<updated_at>` tokens; a moved draft makes
   the whole request 409 "changed meanwhile". Unknown / saved / discarded / foreign ids are silently left out
   (same answer for all; `SELECTION_GONE` when nothing remains).
3. **Foreign wallet/category id** answers `WALLET_NOT_FOUND` / `CATEGORY_NOT_FOUND` (400), identical to an
   unknown id — no oracle (criterion 11 wording "silently excluded" satisfied without a 0-row success).
4. **Save summary via a one-shot httpOnly cookie** (`drafts_saved`, 60 s, read+cleared by `/kotak-masuk`), so a
   crafted URL can never show "Disimpan". "Simpan" with no complete draft stays on the page (400, nothing
   written) instead of redirecting with "Disimpan 0".
5. **List cap 100** (`DRAFT_LIST_MAX`) on both pages, header counts all (`count(*)`), "Menampilkan {n} draf
   terbaru." when more; keeps the selection body under the 8 KiB form cap. Bulk cap 50 (`DRAFT_BATCH_MAX`),
   200 tokens read at most.
6. **Tags use `Badge`, not `Chip`**: `Chip` without `href` renders a pressable `<button>`, wrong semantics for a
   static source label. `DayHeader` gets `inMinor/outMinor = 0` (label only): pending drafts are not money yet
   and demo rows must not feed any total.
7. **`GroupRow` addition** is `selected` / `onToggle` plus `name` / `value` (needed so the checkbox posts
   without JavaScript); other call sites unchanged (test).
8. **Draft whose wallet was archived / category hidden** counts as "belum lengkap" at save time.
9. **`Button` gained `formaction`** (one prop) for the inline and sheet pickers that post the selection form.
10. A dedupe collision with an existing transaction (only possible with a crafted or future capture row)
    refuses the batch with `ALREADY_RECORDED` ("discard that draft, then try again").
