# FN-12 Feature toggles — engineer report (cycle 1)

Branch `fn-12-feature-toggles`, rebased onto `main` 8d1cd51 (originally built on 98df284; pre-rebase branch kept as `fn-12-feature-toggles-pre-rebase`). Risk tier Small.

## What works

- `/pengaturan/fitur` (signed in only): one switch per module (Kekayaan, Langganan, Barang, Koleksi, Ruang
  bersama), all on by default. A flipped switch submits its own row form; it shows the server state (old value
  plus "Menyimpan…" while saving, new value once the write is confirmed and reloaded) and "Perubahan disimpan."
  only after the server answered. Without JavaScript each row has a Simpan button and works as a plain form post.
- Flags are per user (`feature_flags.user_id`, no `space_id`), stored by one upsert on the `(user_id, module)`
  unique index; the user is always `locals.user`, never a form field.
- Hiding Kekayaan removes it from the phone TabBar and the desktop Sidebar on the next layout load (the action's
  `update()` re-runs it; without JS the post re-renders). The TabBar grid is `grid-auto-flow: column;
  grid-auto-columns: 1fr`, so the column count always equals visible tabs + Tambah — no gap. Tab order stays the
  static `TABS` order.
- `/kekayaan` still loads directly when hidden, unchanged, plus a one-line notice with a link back to
  `/pengaturan/fitur`.
- `/pengaturan` index gains a "Fitur" row. Account deletion deletes the user's flags (inside the guarded batch).

## Decisions recorded (auto-accepted defaults)

1. `Module` list and labels live in `src/lib/shared/feature-flags.ts`, not `src/lib/server/feature-flags/modules.ts`
   as the PRD sketched: nav, TabBar and the settings page (client code) need them, and client code must not
   import from `src/lib/server`.
2. Hidden Kekayaan route: loads normally (owner decision D) and shows "Kekayaan disembunyikan dari menu. Angkanya
   tetap dihitung." with a link "Tampilkan lagi di menu" to `/pengaturan/fitur`.
3. Truthful switch: while saving, the switch shows the stored value (disabled, caption "Menyimpan…"); the new
   position appears only after the confirmed write reloads the data. A network error shows the shared "Tidak bisa
   menyimpan…" banner; the switch stays at the stored value.
4. Toggle is `<input type="checkbox" role="switch">` in its own `<label for>`; the native checked state is the
   switch state, so no `aria-checked` is added (ARIA in HTML discourages it on a native checkbox). 44 px target
   (label `min-height: 44px`, switch box 52×44).
5. TabBar grid uses auto columns instead of a computed `repeat(n, 1fr)`: no inline style (CSP forbids it) and no
   per-count class table.
6. If the flags cannot be read, the `(app)` layout shows every nav entry (logged), and `/pengaturan/fitur` shows
   an ErrorState with retry; a display preference never breaks a page.
7. `/pengaturan` index has no server load (it lists static links), so the PRD's skeleton/retry for it is vacuous.
   Kategori is not on this base (FN-05 is on another branch); FN-05 adds its own row to the same index. The index
   keeps its existing Akun and Ruang rows and adds Fitur.
8. `feature_flags.user_id` has no ON DELETE cascade; `deleteAccount` deletes the rows explicitly in its proof-
   guarded batch, like sessions.
